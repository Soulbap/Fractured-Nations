# FRACTURED NATIONS asset pipeline (project skill)

Assets here are **generated by scripts in background Blender 5.2**, never modelled by hand in
a saved scene, and validated **in Godot**, not only in Blender. The generic `blender-*` skills
are the toolbox; this skill says which to use and where our conventions differ.

## Start here
1. `blender-core` for how to run bpy (headless, `--factory-startup`), 5.x API rules, verification.
   Our Blender: `C:/Program Files/Blender Foundation/Blender 5.2/blender.exe` (set `BLENDER_EXE`
   for `run_in_blender.py`). Live MCP sessions are the user's scene: never build assets in it.
2. Read the standard for the family you touch: `docs/ASSET_STANDARD.md` (static assets),
   `docs/CHARACTER_STANDARD.md` (infantry rig, pieces, weapons).
3. Build with **our** entry points, not the skills' modelling scripts:
   * static library: `tools/blender/asset_production/build_assets.py` (`--family`, `--only`,
     `--export`, `--previews`, `--lods`, `--textures`, **`--qa`**, `--qa-strict`, `--qa-sheets`)
   * infantry: `tools/blender/character/build_infantry.py`, factions
     `tools/blender/asset_production/characters/build_factions.py`
   * field structures (WORLD-BASE-01): `tools/blender/structures/*.py`
   A new static asset = a builder function returning `ap_lib.Asset` in a `fam_*.py` module,
   registered in its `BUILDERS` dict. Geometry comes from `ap_kit.py` / `ap_lib.py` primitives
   (boxes, cylinders, lofts) tagged per LOD, collision boxes, markers; textures and the shared
   material table from `ap_textures.py` / `ap_materials.py`.
4. QA gate (BLENDER-SKILLS-01): `build_assets.py -- --only <ids> --qa` runs
   `blender-asset-qa/qa_check.py` and `blender-game-optimization/mesh_stats.py` on LOD0 through
   `tools/blender/asset_production/ap_qa.py`, writes `benchmarks/asset01/qa_report.json` and the
   asset's sidecar `"qa"` block (with `--export`). `--qa-strict` exits 1 on failures;
   `--qa-baseline benchmarks/asset01/qa_baseline.json` makes strict mode fail only on findings
   that are **new** against the recorded baseline (the backlog of known findings is in that file).
   `--qa-sheets DIR` renders random-colour review sheets (`review_shots.py`) to look at.
5. Export + Godot: `--export` writes GLB (+Y up, `export_apply`, vertex colour `Col`, no
   images: materials are swapped in by name on import) + JSON sidecar + StructureDef; then
   `Godot --headless --import` and `benchmarks/asset01/run_lab.sh --validate` (Godot-side
   validator: LOD chain, materials, bounds, collision, markers) and `--shots` for screenshots.
   **An asset is done when the Godot validator passes and its Godot screenshot was looked at.**

## Where our conventions differ from the generic skills
| Topic | Generic skill says | Here |
|---|---|---|
| Forward axis | characters face -Y | **+Y is the front** in Blender (Godot -Z); origin on the ground at the footprint centre |
| LODs | `make_lods.py` decimates `_LOD1.._LOD3` at 50/25/12.5 % | LODs are **authored** per asset (`lods=` on each primitive); names `<id>_LOD0/1/2`, LOD0 first; ranges per family in `ap_lib.LOD_RANGES`; Godot's auto mesh LOD stays on for LOD0 |
| Collision | `-colonly` / `-convcolonly` suffix on the render mesh | separate `COL_<n>-convcolonly` boxes written at export from `Asset.cols`; sidecar `collision_boxes_godot` |
| Materials | 1-2 per asset, `M_*`/`T_*` names, image → Principled | **shared library** `assets/military/materials/<Name>.tres` (51), GLB carries names only, `ap_post_import.gd` binds them; small flat parts fold into `Kit_Palette` (point UVs by design) |
| UVs | unwrap, no overlap, texel density | world-scale **box projection** per face (tile size per material), overlap is intended; palette parts have zero-area UVs: the QA gate runs with the UV check off |
| Export preset | `export_asset.py --preset godot` | `ap_lib.Asset.export` (same exporter; `export_image_format="NONE"`, vertex colours, no extras) - do not add a second exporter |
| Markers | — | `IP_*`, `ATT_*`, `SNAP_*`, `VEH_*`, `WHEEL_*`, `SUSP_*`, `DOOR_*`, `SEAT_*`, `CARGO_*`, `TOW_*`, `WEAPON_*` empties; semantics in ASSET_STANDARD §2 |
| Rig | Rigify / humanoid | one shared CHARACTER-01 skeleton (60 bones), weights transferred from the body (`char_lib.transfer_weights`, `limit_leg_weights`) |
| Done | numbers + a Blender look | numbers + Blender preview **+ Godot validator + Godot screenshot** |

## Which generic skills apply
* `blender-asset-qa` - the gate (wired into `--qa`); run it after every geometry change.
* `blender-game-optimization` - budgets (`mesh_stats`), draw-call reasoning; our LODs are authored, so `make_lods.py` is only for quick experiments.
* `blender-export-pipelines` - glTF/Godot reference (`references/godot-web.md`) and import-suffix facts; the export call itself stays in `ap_lib`.
* `blender-pbr-materials`, `blender-texture-baking` - when adding library materials/textures (`ap_materials.py`, `ap_textures.py`, procedural tileables).
* `blender-character-rigging`, `blender-animation` - infantry work, within CHARACTER_STANDARD.
* `blender-pipeline-automation` - batch / CI patterns (`build_assets.py` already is one).
* Not applicable: Roblox/Unity/Unreal presets, scene setup for hand modelling, rendering/lookdev beyond the preview sheets.

## Known baseline findings (see benchmarks/asset01/qa_baseline.json)
The first gate run over the library recorded real geometry defects the Godot validator does not
see: closed kit boxes with inward normals and coplanar overlapping faces in several assets.
They are tracked there; fix them in the builders (`ap_kit.py` / `fam_*.py`) and regenerate +
re-validate in Godot per asset, not by editing GLBs.
